**Sí, te sirve exactamente igual y el código del frontend (`public/js/...`) no cambia en absoluto.** Deno también tiene servidor HTTP nativo (`Deno.serve`) y SQLite nativo (`node:sqlite` o `jsr:@db/sqlite`) sin necesidad de instalar frameworks pesados.

Las únicas diferencias con respecto a la versión de Bun son:

1. **En `server.js`:** Cambias `import { Database } from "bun:sqlite"` por `import { DatabaseSync } from "node:sqlite"` (soportado nativamente en Deno 2+) y `Bun.serve` por `Deno.serve`.
2. **Despliegue en la nube (Deno Deploy):** Si piensas subirlo a **Deno Deploy** para el enlace público de la entrega, ten en cuenta que Deno Deploy no permite escribir archivos `.db` locales en disco de forma permanente; en ese caso te conviene conectar `server.js` a **Neon Tech (PostgreSQL)** o **Turso (LibSQL/SQLite remoto)** usando una variable de entorno `DATABASE_URL` para que el historial sobreviva al reiniciar.
3. **Permisos:** Al ejecutarlo en local usarás `deno run --allow-net --allow-read --allow-write server.js`.

### Adaptación directa de `server.js` para Deno

Si decides usar Deno en local con SQLite, reemplaza la cabecera de `server.js` por esta:

```javascript
import { DatabaseSync } from "node:sqlite";
import { serveDir } from "jsr:@std/http/file-server";

Deno.mkdirSync("db", { recursive: true });
const db = new DatabaseSync("db/simtele.db");
const schema = Deno.readTextFileSync("db/schema.sql");
db.exec(schema);

// ... (las consultas prepare().run() / .all() / .get() funcionan idéntico con DatabaseSync)

```
